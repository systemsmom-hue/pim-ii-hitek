# Sprint 08 — Programação Estruturada em C

A Sprint 08 representa a etapa planejada para implementação das principais funcionalidades do **Sistema de Gestão de Comissões — Hitek Informática** utilizando a linguagem C.

Nesta etapa, serão selecionadas funcionalidades do sistema que possam ser representadas por meio de Programação Estruturada, mantendo coerência com os requisitos, regras de negócio, diagramas e fluxo já definidos no projeto.

> Esta Sprint ainda não foi concluída. As atividades abaixo representam o planejamento da etapa de Programação Estruturada em C.

---

## Status

**Planejada**

---

## Objetivo da Sprint

Selecionar e implementar em linguagem C funcionalidades representativas do sistema, utilizando os principais conceitos de Programação Estruturada exigidos pela disciplina.

## Seleção das funcionalidades

Antes da implementação, deverão ser escolhidas as funcionalidades mais adequadas para representação em C.

A escolha deverá considerar:

- relevância para o sistema;
- possibilidade de implementação por meio de Programação Estruturada;
- relação com os requisitos funcionais;
- relação com as regras de negócio;
- possibilidade de demonstrar os conceitos exigidos pela disciplina.

As funcionalidades definitivas ainda serão selecionadas durante esta Sprint.

---

## Processo de desenvolvimento

Para cada funcionalidade escolhida, deverá ser seguido um fluxo semelhante a:

```text
Funcionalidade do sistema
        ↓
Algoritmo
        ↓
Fluxograma
        ↓
Pseudocódigo
        ↓
Código em C
        ↓
Teste
        ↓
Resultado
```

O objetivo é manter coerência entre todas as representações da mesma funcionalidade.

---

## Algoritmos

Antes da implementação, deverão ser definidos os passos necessários para cada funcionalidade.

O algoritmo deverá deixar claro:

- quais dados serão recebidos;
- quais operações serão realizadas;
- quais decisões serão necessárias;
- quais repetições serão utilizadas;
- qual resultado será produzido.

---

## Fluxogramas

As funcionalidades escolhidas deverão possuir fluxogramas quando exigido pela disciplina.

Os fluxogramas deverão representar visualmente:

- início;
- entrada de dados;
- processamento;
- decisões;
- repetições;
- saída de dados;
- fim.

Eles deverão permanecer coerentes com o pseudocódigo e com a implementação em C.

---

## Pseudocódigos

Antes da implementação definitiva, poderão ser desenvolvidos pseudocódigos para representar a lógica das funcionalidades.

Exemplo de estrutura:

```text
INÍCIO

    ler dados

    processar dados

    se condição então
        executar ação
    senão
        executar outra ação
    fim se

    exibir resultado

FIM
```

Os pseudocódigos definitivos dependerão das funcionalidades selecionadas.

---

## Implementação em C

O código-fonte será armazenado em:

```text
src/c/
```

A estrutura interna será definida conforme as funcionalidades selecionadas.

O código deverá utilizar Programação Estruturada e permanecer relacionado ao Sistema de Gestão de Comissões.

---

## Estruturas condicionais

As implementações deverão utilizar estruturas condicionais quando necessárias.

Exemplos:

```c
if
else
switch
```

Essas estruturas poderão ser utilizadas para representar decisões presentes nas regras de negócio.

---

## Estruturas de repetição

Também deverão ser utilizadas estruturas de repetição quando adequadas às funcionalidades selecionadas.

Exemplos:

```c
for
while
do while
```

A utilização deverá possuir finalidade real dentro do algoritmo implementado.

---

## Funções

A implementação deverá utilizar funções para dividir as responsabilidades do programa.

Estrutura geral:

```c
tipo nomeFuncao(parametros) {
    // processamento
}
```

As funções deverão possuir nomes relacionados às operações que executam.

---

## Vetores

O projeto deverá utilizar vetores quando adequados às funcionalidades selecionadas.

Eles poderão ser utilizados para armazenar conjuntos de informações durante a execução do programa.

A utilização definitiva será definida durante a implementação.

---

## Matrizes

Também deverá ser avaliada a utilização de matrizes no contexto das funcionalidades selecionadas.

A matriz deverá ser utilizada somente quando houver uma necessidade coerente com a lógica implementada.

---

## Manipulação de arquivos

A necessidade de utilização de arquivos deverá ser avaliada durante a Sprint.

Caso seja utilizada, a manipulação poderá permitir preservar informações entre diferentes execuções do programa.

A decisão deverá ser baseada nas funcionalidades implementadas e nas exigências da disciplina.

---

## Testes

Cada funcionalidade implementada deverá ser testada.

Os testes deverão verificar:

- funcionamento esperado;
- resultados dos cálculos;
- comportamento das condições;
- comportamento das repetições;
- tratamento das entradas previstas;
- coerência com as regras de negócio.

---

## Resultados

Os resultados obtidos durante os testes deverão ser apresentados e explicados.

Quando aplicável, poderão ser registrados:

- entradas utilizadas;
- processamento realizado;
- saída produzida;
- resultado esperado;
- resultado obtido.

---

## Coerência com o projeto

A implementação em C deverá permanecer relacionada aos artefatos já desenvolvidos.

O fluxo deverá ser:

```text
Requisito funcional
        ↓
Regra de negócio
        ↓
Função do sistema
        ↓
Algoritmo
        ↓
Fluxograma
        ↓
Pseudocódigo
        ↓
Código em C
        ↓
Resultado
```

Nenhuma funcionalidade deverá ser implementada apenas para demonstrar sintaxe sem relação com o Sistema de Gestão de Comissões.

---

## Relação com o Diagrama Estendido

O Diagrama Estendido apresenta as principais funções previstas para os módulos do sistema.

Durante esta Sprint, ele poderá ser utilizado como referência para selecionar quais funções serão representadas em C.

Entre os módulos disponíveis estão:

```text
VENDAS
FINANCEIRO
COMISSÕES
USUÁRIOS
COLABORADORES
PAGAMENTOS
RELATÓRIOS
CONFIGURAÇÕES
```

A seleção definitiva das funções será realizada antes do início da implementação.

---

## Critérios para conclusão da Sprint

A Sprint 08 somente deverá ser marcada como concluída quando:

- as funcionalidades tiverem sido selecionadas;
- os algoritmos estiverem definidos;
- os fluxogramas estiverem concluídos;
- os pseudocódigos estiverem concluídos;
- o código em C estiver implementado;
- as estruturas exigidas pela disciplina tiverem sido utilizadas adequadamente;
- os testes tiverem sido realizados;
- os resultados estiverem documentados;
- houver coerência entre fluxograma, pseudocódigo, código e resultado.

---

## Resultado esperado

Ao final desta Sprint, o projeto deverá possuir um conjunto de funcionalidades implementadas em linguagem C, acompanhadas de seus respectivos algoritmos, fluxogramas, pseudocódigos, testes e resultados.

A implementação deverá demonstrar a aplicação dos conceitos de Programação Estruturada dentro do contexto real do Sistema de Gestão de Comissões.
